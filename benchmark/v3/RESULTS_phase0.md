## Reading notes

- `dense_fallback` returns 10 chunks, so its Recall@20 column is effectively Recall@10.
- The README pin only ever replaces the 5th result, so Hit@1 and ranks 1-4 are identical for `production` and `production_no_pin`; any difference is the pin's effect.
- MMR's order is discarded by LangChain's Chroma wrapper, so `dense_fallback` and `dense_plain` share their top-1 (identical Hit@1).
- Tune on **dev** only; **holdout** confirms a change once, at the end.

## Unanswerable queries: top-1 signal for a later refusal threshold

Not scored for Hit/MRR. Median [p10, p90] of each arm's top-1 signal; `cosine` is the production embedding of the query against the top-1 chunk (one scale for every arm), `native` is the arm's own score (RRF for fused arms, BM25 score for bm25). A usable threshold needs the unanswerable distribution below the answerable one. The RRF score is bounded by rank arithmetic (a top-1 found by both lists scores 0.5/61 + 0.5/61 = 0.016 with this configuration), so it carries no confidence information.
